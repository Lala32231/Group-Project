# Портал групи

Веб-портал студентської групи на Django: головна сторінка з віджетами, автентифікація
з трьома ролями доступу, новини, форум, події/календар, опитування (голосування),
оголошення, галерея та портфоліо.

## Технології

- **Backend:** Django (Class-Based Views), Django sessions — для захисту від повторного
  голосування в опитуваннях без прив'язки до акаунту.
- **Frontend:** HTML-шаблони + Bootstrap 5 (CDN).
- **БД:** SQLite (за замовчуванням, легко змінити в `settings.py`).
- **Безпека:** стандартна автентифікація Django (хешування паролів, CSRF-захист,
  сесії), кастомна модель користувача з полем `role`.

## Дизайн і зміна фону сайту

Портал оформлений у темній "glass"-стилістиці (напівпрозорі картки, розмиття фону,
шрифти Space Grotesk / Inter). Фонове зображення можна змінити без правок коду:

1. Увійдіть під акаунтом з роллю **Адміністратор**.
2. У верхньому меню відкрийте пункт **"Оформлення"** (`/settings/`).
3. Завантажте своє фото — воно розтягнеться на весь екран як фон сайту.
4. Повзунком **"Затемнення фону"** відрегулюйте контраст, щоб текст залишався читабельним.

Це реалізовано через модель `core.SiteSettings` (singleton-запис) — фон можна також
змінити через `/admin/core/sitesettings/`.

## Ролі доступу

| Роль | Опис |
|---|---|
| `user` (Користувач) | базова роль після реєстрації: читання контенту, участь у форумі, опитуваннях, портфоліо |
| `moderator` (Модератор) | + створення/редагування новин, подій, оголошень, тем форуму, галереї |
| `admin` (Адміністратор) | + управління ролями користувачів, повний доступ через `/admin/`. Викладач і керівник проекту повинні мати цю роль |

Ролі перевіряються через міксини `ModeratorRequiredMixin` / `AdminRequiredMixin`
(`accounts/permissions.py`), які використовуються у в'юшках (Class-Based Views).

## Запуск проєкту

```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install django pillow

cd group_portal
python manage.py migrate
python manage.py createsuperuser   # створити викладача/адміністратора
python manage.py runserver
```

Відкрити http://127.0.0.1:8000/

Після створення суперкористувача не забудьте задати йому роль "admin" —
або через адмінку (`/admin/`), або так:

```bash
python manage.py shell -c "
from accounts.models import User
u = User.objects.get(username='ВАШ_ЛОГІН')
u.role = User.Role.ADMIN
u.save()
"
```

**Тестовий адміністратор, створений під час розробки:**
логін `admin`, пароль `admin12345` (обов'язково змінити перед здачею проєкту).

## Структура проєкту

```
group_portal/
├── accounts/        # користувачі, ролі, реєстрація/вхід, профілі
├── core/             # головна сторінка з віджетами
├── news/              # новини групи
├── forum/             # форум (теми + повідомлення)
├── events/            # події та календар
├── polls_app/         # опитування/голосування (на Django sessions)
├── announcements/     # оголошення
├── gallery/           # галерея (альбоми + фото)
├── portfolio/         # портфоліо студентів
├── templates/         # base.html, партіали
└── static/            # css
```

## Що ще не реалізовано (можна розширити)

Відповідно до ТЗ портал розрахований на розширення функціоналу. Наразі не
реалізовано (не було в наданому фрагменті ТЗ або є на розсуд команди):

- **Електронний щоденник** — потрібні уточнення структури (оцінки/розклад/предмети),
  не було деталей у ТЗ.
- **Матеріали** (окремий розділ навчальних матеріалів) — зараз частково покривається
  "Портфоліо" і файлами в новинах/подіях.
- Розмежування "опитування" і "голосування" як двох окремих систем — зараз об'єднано
  в один модуль `polls_app`, оскільки в ТЗ не було чіткого технічного розділення.
- Сповіщення, коментарі, лайки, пошук по сайту.

Ці модулі можна додати за тим самим патерном (Django app + CBV + шаблони), який уже
використаний в проєкті.
